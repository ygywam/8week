# 8주 루틴

모바일 중심 운동·걷기·체중 기록 웹앱입니다. 운동 과정은 앱에 들어 있으며 Notion을 연결하지 않습니다. Supabase 계정으로 사용자별 데이터를 저장하고, Gemini 채팅은 각 사용자의 API 키로 동작합니다.

## 현재 상태와 주의

- 56일 일정, 체크, 체중·변화, 안내 UI는 로컬 미리보기에서 검증했습니다. 미리보기는 메모리에서만 동작하며 새로고침 시 기록이 삭제됩니다.
- 실제 Supabase 인증·RLS·멀티기기 동기화·Gemini·Vercel 배포·iOS/Android 홈 화면은 **연결 전으로 검증되지 않았습니다**. 실데이터나 공개 운영 전 아래 점검을 끝내세요.
- 운동·체중·대화는 민감한 개인 정보일 수 있습니다. 계정별 분리, 개인정보 처리 고지, 서비스 제공자의 약관 및 비용을 반드시 확인하세요. 앱은 의료 진단·처방용이 아닙니다.
- Gemini 키는 브라우저의 현재 계정별 localStorage에 저장됩니다. 공유 기기, 브라우저 확장, 악성 스크립트에 노출될 수 있습니다. 키는 요청할 때만 Vercel 서버를 통과하며 DB와 Git에 저장하지 않도록 구성했습니다. 비밀 관리의 완전한 보안을 보장하지 않습니다. 키 제한·사용량 경고를 설정하세요. Google은 운영 환경에서 서버 측 비밀 관리를 권장합니다: https://ai.google.dev/gemini-api/docs/api-key
- AI 질문과 이전 대화는 Google로 전송됩니다. 운동·체중 정보를 자동으로 가져오지 않으며, 체크할 때만 이번 요청에 추가합니다. 사용자가 직접 대화에 적었거나 AI가 이전에 되풀이한 내용은 이후 대화 이력에 포함될 수 있습니다. Google 무료·유료 서비스의 데이터 처리 차이를 확인하세요: https://ai.google.dev/terms

## 파일 구성

- `public/`: HTML, CSS, 동작 코드, 원본 SVG와 홈 화면/탭 아이콘
- `api/chat.js`: 로그인 확인 후 개인 Gemini 키를 일시적으로 전달하는 Vercel 함수
- `supabase/schema.sql`: 데이터 테이블, 소유자별 RLS, 시작일 변경 함수
- `build.mjs`: Vercel 환경변수를 공개 클라이언트 설정으로 주입
- `tests/`: 일정 단위 테스트 및 로컬 Playwright 화면 테스트

## 1. Supabase 설정

1. 본인의 Supabase 프로젝트를 만듭니다. 프로젝트 URL과 **publishable key**(또는 기존 anon 공개 키)를 확인합니다. `service_role`/secret 키는 절대 사용하지 마세요.
2. 새 프로젝트의 SQL Editor에서 `supabase/schema.sql`을 한 번 실행합니다. 기존 데이터가 있는 프로젝트에 적용하기 전에는 충돌을 확인하고 별도 테스트 프로젝트를 권장합니다.
3. Authentication의 이메일/비밀번호 로그인을 활성화합니다. 이메일 확인 설정에 따라 가입자가 확인 링크를 눌러야 로그인할 수 있습니다. 서비스 제공 이메일 제한과 실제 운영용 SMTP 설정을 확인하세요.
4. Authentication의 Site URL과 허용 Redirect URL에 실제 Vercel 배포 주소를 등록하고, Supabase 대시보드에서 사용하는 인증 이메일 템플릿과 URL을 확인합니다.
5. RLS가 켜져 있는지 확인합니다. 실제 서로 다른 두 계정으로 각 테이블의 읽기·쓰기·삭제가 본인 행에만 허용되는지 직접 시험하세요. SQL 파일을 배포하는 것만으로 실환경 검증이 끝난 것은 아닙니다.

## 2. GitHub와 Vercel

1. 이 폴더의 파일을 GitHub 저장소에 올립니다. `.env` 파일, 실제 API 키, Supabase secret/service_role 키, 개인 기록은 올리지 마세요.
2. Vercel에서 해당 저장소를 가져옵니다. Framework Preset은 Other, Build Command는 `npm run build`, Output Directory는 `dist`입니다 (`vercel.json`에 포함).
3. Vercel 프로젝트 환경변수에 `SUPABASE_URL`과 `SUPABASE_PUBLISHABLE_KEY`를 설정합니다. 이 값은 브라우저에도 공개되는 값이므로 공개 가능한 프로젝트 URL과 publishable/anon 키만 사용합니다. 두 변수는 배포 빌드와 서버 함수 모두에 필요합니다.
4. 배포 후 실제 URL을 Supabase 인증 설정에 등록하고 필요하면 재배포합니다. 환경변수를 바꿨을 때도 재배포해야 브라우저 설정이 갱신됩니다.
5. 로그인, 이메일 확인, 생성·수정·새로고침, 다른 기기 동기화, 다른 계정의 접근 차단, 채팅 및 에러 처리, 홈 화면 추가를 검증합니다. 모바일 브라우저에서 홈 화면 추가 가능 여부는 플랫폼별로 다릅니다.

## 3. Gemini 설정과 사용

1. 각 사용자는 Google AI Studio에서 본인의 Gemini API 키를 만듭니다: https://aistudio.google.com/apikey
2. 앱의 설정에서 개인 키를 입력합니다. 키는 현재 계정과 브라우저에만 저장되고 다른 기기로 이동하지 않습니다. 로그아웃해도 이 브라우저에 남으므로 공유 기기에서는 '키 삭제'를 사용하세요.
3. 채팅에서 질문합니다. 현재 운동·최근 체중을 함께 보낼 때만 체크박스를 선택합니다. 대화 이력도 함께 전송되므로 민감 정보를 직접 입력할 때 주의하세요.
4. Gemini 모델은 `api/chat.js`의 `gemini-2.5-flash`로 지정되어 있습니다. 가용성과 요금은 실제 계정 및 Google 정책에 따라 달라질 수 있습니다. 키가 유출되면 Google에서 폐기하고 새 키를 발급하세요.

## 기록과 초기화

- 완료율 = 하루 완료로 표시한 날짜 수 ÷ 56 × 100. 개별 항목 체크와 하루 완료는 별도로 관리합니다.
- 시작일 변경 시 운동 체크 전체가 삭제되고, 체중과 대화는 유지됩니다. 변경 전 확인 창이 나타납니다.
- 체중은 하루에 한 값이며 재입력 시 해당 날짜의 값이 바뀝니다. 변화량은 가장 오래된 기록과 가장 최근 기록의 차이입니다.
- 설정에서 기록을 JSON으로 내보내거나 삭제할 수 있습니다. 현재 버전은 JSON 가져오기를 제공하지 않습니다. 계정 자체 삭제는 Supabase 프로젝트 관리자가 처리해야 합니다. 삭제는 여러 요청으로 이루어져 네트워크 오류가 나면 일부만 삭제될 수 있으므로 다시 확인하세요.
